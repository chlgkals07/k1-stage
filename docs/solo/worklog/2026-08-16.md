## 1. 로봇 AP 를 `192.168.50.1` → `192.168.60.1`

### 증상

새 장소에서 `run.sh` 가 무선 경로를 못 찾고 USB(55.1)로 폴백했다. USB 를 빼면 로봇에
닿는 길이 하나도 없었다.

### 원인

**장소 공유기가 하필 `192.168.50.1` 이었다.** 로봇 AP 와 같은 번호다.

```
$ ip route get 192.168.50.1
192.168.50.1 dev enp129s0 src 192.168.50.24     ← 유선(공유기). Wi-Fi 아님
$ curl -k https://192.168.50.1:8443/
<script>window.top.location.href='/Main_Login.asp';</script>   ← 공유기 관리자 페이지
```

같은 번호의 망이 둘이면 커널은 목적지마다 인터페이스를 하나만 고른다. metric 이 낮은
유선이 이겨서 `192.168.50.1` 이 전부 공유기로 빨려 들어갔다. **설정으로 우회할 수 있는
문제가 아니다.**

`Main_Login.asp` + `httpd/3.0` 은 ASUS 공유기이고, **ASUS 의 공장 초기 LAN 주소가 정확히
`192.168.50.1`** 이다. 즉 이 충돌은 이 장소의 우연이 아니라 **ASUS 공유기가 있는 곳이면
어디서나 재발한다.** 전 장소는 랜이 `192.168.10.x` 라 안 겹쳤을 뿐이다
(`STATUS_AND_HANDOVER.md` 에 `192.168.10.58` 로 기록돼 있다).

### 조치

로봇 쪽 한 줄이 전부다. dnsmasq 가 아니라 **systemd-networkd 내장 DHCP** 를 쓴다.

```
/etc/systemd/network/75-wifi-ap.network
  Address=192.168.50.1/24  →  192.168.60.1/24     (백업 .bak.ap60_20260816)
  DHCPServer PoolOffset=50 PoolSize=100 그대로 → 60.50~60.149 배포
```

SSID·비밀번호·ROS·모션·gateway 코드는 안 바뀐다 (gateway 는 `0.0.0.0:8443` 바인딩).

**자기가 타고 있는 링크를 끊는 변경**이라 스크립트에 10분 워치독을 붙였다. 새 주소로
접속해 commit 파일을 남기지 않으면 로봇이 스스로 되돌린다. 확인 후 commit 했다.

### PC 쪽 필수 설정

```bash
nmcli connection modify k1-orinnx10 ipv4.never-default yes \
                                    connection.autoconnect-priority 10
```

- `never-default` — 로봇 AP 에는 인터넷이 없다. 기본 경로로 쓰면 안 된다
- `autoconnect-priority` — **우선순위를 안 주면 NetworkManager 가 장소 Wi-Fi 로 조용히
  되돌아가 SSH 가 끊긴다.** 작업 중 실제로 두 번 겪었다

### 결과

```
enp129s0    192.168.50.24   ← 장소망: 인터넷 + 폰
wlp128s20f3 192.168.60.77   ← 로봇
```

USB 없이 무선으로 양쪽이 동시에 산다. `run.sh`·`check_modes.sh`·문서의 주소를 갱신했다.

## 2. 관객용 화면 `/pad`

### 왜

실기에서 두 가지가 걸렸다. **로봇에서 소리가 안 나서** 폰에서 나오는 목소리가 로봇의
말로 안 들리고, **현장 소음에 말을 잘못 알아들어** 엉뚱한 응답이 잦았다.

그래서 현장 구성을 바꿨다. RC(안전) / 아이패드(진행자→관객) / 모니터(자막) / 운영자 화면.
**관객은 명령만 내리고, 로봇은 소리로 답하지 않는다.** 응답은 `/display` 에 글로만 뜬다.

### 세 번째 허용목록

```
api_allowlist  73   운영자가 누를 수 있는 전부
llm_allowlist  21   모델이 스스로 고를 수 있는 것        (불변)
pad_allowlist  12   관객이 누를 수 있는 것               ← 신규
pad_llm_exclude 3   /pad 음성 경로에서만 빼는 것         ← 신규
```

`pad_allowlist` 기준은 `api_allowlist ∩ safety:safe ∩ 관객 친화 카테고리`. 후보가 23개인데
그중 **llm 승격까지 거쳐 물리 검증이 끝난 12개**를 출발점으로 했다.

`_play()` 가 이미 `source == "llm"` 일 때만 목록을 강제하고 있었다. 같은 자리에 `pad` 분기를
더했다 — **새 안전 로직을 짜지 않고 목록만 하나 더 건다.** 운영자 경로(`manual`)는 불변이다.

`pad_llm_exclude` 는 명시 요청 전용 3종(팔굽혀펴기·재즈핸즈·**카트휠**)이다. 카트휠은
*최대 공간 + E-stop 대기* 가 전제인데 관객이 말로 "옆돌기 해줘" 하면 나간다.
`llm_allowlist` 자체는 건드리지 않고 **세션 빌드 시점에만** 뺀다.

### 음성 응답 끄기

`build_session(pad=True)` 이 `output_modalities: ["text"]` 를 낸다. 실제 API 로 확인했다.

- 모델이 오디오를 **생성하지 않는다** → 소리 문제가 원인부터 사라지고 TTS 지연이 통째로 빠진다
- 입력 전사와 함수 호출은 그대로 → 관객 말은 여전히 알아듣고 동작도 고른다
- 이벤트가 `response.output_audio_transcript.*` → **`response.output_text.*`** 로 바뀐다

```
/pad 세션 : output_modalities ['text']  · 도구 18 · 카트휠 없음
/ 폰 세션 : output_modalities ['audio'] · 도구 21 · 카트휠 있음   (불변)
```

### 화면

`static/pad.html` 신규. 버튼 12개가 한 화면에, 큰 터치 영역, **한글 이름만**(영문 state 숨김),
하단에 PTT 버튼. 상태는 `준비됐어요`/`듣고 있어요`/`하는 중이에요`/`잠깐만요` 4가지로 뭉갠다 —
`cooldown 8초` 같은 운영 문구는 관객에게 보이지 않는다(원인은 `/operator` 로그에 그대로 남는다).
정지 버튼·로그·상태카드·음성설정 없음. **`pc.ontrack` 을 붙이지 않아** 설정이 바뀌어도 소리가
새지 않는다.

`index.html` 은 **수정하지 않고 복사했다.** 공통 JS 로 묶으면 두 화면이 같은 코드를 쓰지만

`/pad` 가 현장 검증된 뒤에 묶는다.

`K1_UI_TOKEN` 하나를 네 화면이 공유한다. **아이패드에서 주소를 `/operator` 로 바꾸면

## 4. 모니터가 클립을 튼다 — 패드 12개 확정

버튼을 누르면 `/display` 가 자막을 덮고 그 동작의 sim 클립을 전체화면으로 튼다.
끝나면 자막으로 돌아온다.

### 배관은 새로 안 만들었다, 신호만 더했다

`/conversation` 폴링(300ms)을 그대로 쓴다. 다만 두 가지가 없었다.

- **`current_motion` 은 한 번 설정되면 안 지워졌고**, `rev` 는 자막 delta 에도 올라
  "동작이 시작됐다"를 구분할 수 없었다 → **`motion_rev`** 신설. 동작이 실제로 나갈 때만
  오른다. 같은 버튼을 두 번 눌러도 값이 바뀌므로 다시 재생된다
- 클립 파일은 영문 `state` 로 찾는데 한글 이름만 내려주고 있었다 → **`current_motion_state`** 추가

`clear_conversation()` 은 `motion_rev` 를 **되돌리지 않는다.** 되돌리면 모니터가 새 동작으로
오해해 이미 끝난 클립을 다시 튼다.

## 6. display 상태 화면 + preview 실행 + dance 를 display 로 (2026-08-17)

### stage 상태 기계 (서버가 단일 진실 공급원)

`idle | listening | thinking | preview | executing | dance`. display 는 서버만 본다.
