# 새 장소 셋업 가이드 (무선 전제)

2026-08-13 실기에서 PC↔로봇 구간에 `No route to host` 가 났다. **유선은 쓰지 않기로 했으므로**
그 구간을 튼튼하게 만드는 것이 이 문서의 목적이다.

## 네트워크 구성

```
폰 ──(전용 Wi-Fi)── 휴대용 라우터 ──── PC ──(로봇 AP Wi-Fi)── K1
                                      └──(인터넷)── OpenAI
```

| 구간 | 무엇을 쓰나 | 왜 |
|---|---|---|
| 폰 ↔ PC | **휴대용 라우터** | 장소 Wi-Fi 에 의존하지 않는다. 게스트망은 기기 간 통신이 막혀 있는 경우가 많아 폰이 PC 에 못 붙는다 |
| PC ↔ 로봇 | 로봇 AP (`k1-orinnx10`) | **PC 를 로봇 가시선 안, 가능한 가까이.** 여기가 어제 끊긴 구간이다 |
| PC ↔ 인터넷 | 라우터 WAN / 유선 / 폰 테더링 | OpenAI 호출용. 없으면 음성이 안 되고 버튼만 동작한다 |

**PC 는 로봇 AP 와 인터넷에 동시에 붙어야 한다** (Wi-Fi + 유선, 또는 Wi-Fi 어댑터 2개).

### 로봇 AP 주소: `192.168.60.1` (2026-08-16 변경)

원래 `192.168.50.1` 이었는데, **ASUS 공유기의 공장 초기 LAN 주소가 정확히 그 값이다.**
장소 공유기가 ASUS 면 PC 라우팅 테이블에 `192.168.50.0/24` 가 두 개 생기고, 커널은
목적지마다 인터페이스를 하나만 고르므로 `192.168.50.1` 이 전부 공유기로 빨려 들어가
**로봇에 영원히 닿지 못한다.** 설정으로 우회할 수 있는 문제가 아니라 구조적이다.

`192.168.60.x` 는 공유기 초기값으로 거의 쓰이지 않아 재발 확률이 낮다. 바뀐 것은
로봇 `wlan0` 주소와 DHCP 대역뿐이고 **SSID·비밀번호는 그대로** 다.

| 대역 | 쓰임 |
|---|---|
| `192.168.60.1` | 로봇 gateway (AP `k1-orinnx10`), PC 는 `192.168.60.50~149` 를 받는다 |
| `192.168.55.1` | 로봇 USB — 복구용 폴백. 운영 경로 아님 |
| 장소 대역 | 폰 ↔ PC, 인터넷 |

로봇 쪽 실체는 `/etc/systemd/network/75-wifi-ap.network` 의 `Address=` 한 줄이다
(백업 `.bak.ap60_20260816`). dnsmasq 가 아니라 systemd-networkd 내장 DHCP 를 쓴다.

**PC Wi-Fi 프로파일 권장 설정** — 로봇 AP 는 인터넷이 없으므로 기본 경로로 쓰면 안 된다:

```bash
nmcli connection modify k1-orinnx10 ipv4.never-default yes
```

## 준비물

- 휴대용 라우터 (또는 폰 핫스팟 — 단 PC 가 로봇 AP 와 동시 연결 가능해야 한다)
- PC 를 로봇 근처에 둘 받침대 / 연장 전원
- E-stop 담당자

## 코드 쪽 대비 (2026-08-14 반영)

- relay 가 로봇 연결을 **재사용**한다 (keep-alive). 요청마다 TLS 핸드셰이크를 새로 하던
  것이 불안정 Wi-Fi 에서 실패를 누적시켰다
- **연결 실패에만 1회 재시도**한다. 로봇이 내린 거부는 재시도하지 않는다 —
  같은 동작이 두 번 실행되면 안 된다
- 실패 사유가 `로봇 연결 끊김` / `로봇 gateway 오류` 로 구분돼 로그·UI 에서 원인이 보인다
- 끊겨도 로봇은 자기 상태를 유지한다 (어제 확인됨)

## 현장 순서

```bash
# 1. 라우터 켜고 폰·PC 를 거기에 연결. PC 는 로봇 AP 에도 연결
# 2. 로봇: go  (사람이 직접)
# 3. PC:
cd /home/robotis-ai/Projects/shape3/motion_llm
./run.sh --deploy
```

- `run.sh` 가 링크·ROS·파일 md5 를 점검하고 실패 지점을 알려준다
- 폰은 북마크한 고정 URL 로 접속 (토큰이 고정이라 매번 같다)
- 자막 모니터는 같은 URL 에 `/display` — 한 번 열어두면 계속 따라간다

## 확인 순서

1. `/operator` 에서 `API 준비됨`
2. **정지 버튼** 먼저 (실행 중에도 눌리는지)
3. 인사 3종 회귀
4. 그다음 데모

## 끊겼을 때

- 로봇은 그대로 유지된다. 당황하지 말 것
- `/operator` 상단에 `로봇 연결 끊김` 이 뜨면 PC 를 로봇 쪽으로 옮긴다
- relay 만 다시 띄우면 된다: `Ctrl-C` 후 `./run.sh`
- 위험하면 **RC Damping / E-stop** (네트워크와 무관하게 항상 동작한다)
