# group_stage 런북 — K1 뉴진스 군무 (라디오 N대 동시 발사)

연결된 RadioMaster Pocket **전부**에 같은 명령이 같은 순간에 나간다.
꽂은 라디오 수 = 같이 춤추는 로봇 수 (1~4대, 자동 인식).
단일 로봇·Wi-Fi 운영은 `../solo_stage`(run.sh). 이 앱은 **RC 무대 전용**이다.

## 1. 라디오 준비 (대마다, 매번)

| # | 할 일 | 확인 |
|---|---|---|
| 1 | 전원 ON | ROBOT 화면 정상 |
| 2 | **위쪽 USB-C** → PC 연결 → 팝업 **Serial** | 아래쪽은 충전 전용이라 인식 안 됨 |
| 3 | SYS → Hardware → USB-VCP = **LUA** | 재부팅하면 CLI 로 리셋되는 기종이 있다 |
| 4 | SYS → Tools → **K1PC** 실행 | 화면 `K1PC v2.3 IDLE` |
| 5 | **SB 중앙**, SC 상단 | SB 하단이면 발사 1초 뒤 미믹이 끊긴다 |

> **K1PC 화면은 계속 떠 있어야 한다.** 다른 메뉴로 나가면 그 라디오는 명령을 못 받는다.
> 화면 자체가 "PC 제어 중" 표시다.

**USB 포트**: 어디든 된다(물리 포트 경로로 자동 식별). 단 4포트 허브는 이미 조명·쿨러가
2칸을 쓰고 있으니, 4대를 붙이려면 **전원 어댑터 있는 허브**나 메인보드 포트 분산을 쓴다.

## 2. 서버 켜기

```bash
cd ~/Projects/shape3/k1-stage/group_stage
./start_stage.sh          # tmux 세션 rc-stage 로 기동, HTTPS + 고정 토큰
```

끝나면 접속 확인용 200 두 줄이 찍힌다. 로그는 `tmux attach -t rc-stage` 또는 `logs/server.log`.
`--https` 없이 띄우면 **외부 기기에서 로그인이 안 된다**(쿠키 Secure 플래그).

## 3. 화면 배치

토큰은 `~/.k1/secrets.env` 의 `K1_STAGE_TOKEN`(고정, 안 바뀜).
`<IP>` = 유선 `192.168.10.58`, 원격 `100.86.174.82`.

| 화면 | 어디서 | 주소 |
|---|---|---|
| 운영자 | 조작용 노트북/패드 | `https://<IP>:19000/operator?token=<TOKEN>` |
| **무대(음악·영상)** | **TV** (스피커 있는 기기) | `https://<IP>:19000/display?token=<TOKEN>` |
| 댄스 싱크 보정 | 필요 시 | `https://<IP>:19000/dance?token=<TOKEN>` |

자체 서명 인증서라 첫 접속 때 **고급 → 계속 진행**. 한 번 열면 이후 토큰 없이 들어가진다.

> **음악은 display 를 연 기기에서 나온다** (로봇·서버가 아님). 그리고 브라우저 정책상
> **첫 재생 전에 display 화면을 한 번 탭/클릭해 오디오 잠금을 풀어야** 소리가 난다.
> 안 풀면 영상만 나오고 무음이다. 무대 시작 전에 미리 해 둔다.

## 4. 무대 진행

1. 운영자 화면에서 **라디오 N/N대** 확인 (안 맞으면 **[USB 재탐색]**)
2. 로봇들이 Damping 이면 **정지 버튼** 한 번 (Velocity 로 깨움) — 부팅 직후엔 미믹이 안 나간다
3. display 오디오 잠금 해제 (3장 참고)
4. 무대 섹션 → 프리셋 **`newjeans-rc`** → **시작**
   - 발사 1.5초 전 전 라디오에 PREP, 예약 시각 정각에 FIRE 동시
   - 영상이 끝나거나 37초쯤 뒤 무대 자동 종료
5. **첫 발사는 눈으로 전 대 확인** (아래 한계 참고)
6. 끝나면 각 라디오 SB 하단으로 내려 보행 복귀

## 5. 안전

- 라디오 각각이 **자기 로봇의 물리 E-stop**: **SC 하단 = Damping**. 펄스 1초 구간 밖에서
  항상 물리가 우선이다. 라디오는 손 닿는 곳에 나란히 둔다
- 미믹을 손으로 끊으려면 그 라디오 **SB 하단**(즉시 보행으로 빠짐)
- PC/케이블이 죽으면 keepalive 끊김으로 **0.5초 내 물리 조종 복귀** (라디오별 독립)
- PC 는 스틱(CH1~4)·API arm(CH8)·E-stop(CH12)을 절대 건드리지 않는다

## 6. 알려진 한계 (반드시 알고 운영할 것)

1. **로봇이 실제로 췄는지 시스템은 모른다.** 로봇에서 돌아오는 신호가 없어서, 라디오까지
   성공하면 화면에 "N/N대 발사 · 발사 관측 OK"로 뜬다. 한 로봇이 안 움직여도 초록불이다.
   → **눈으로 확인**하고, 안 움직인 로봇은 219 등록·자산 배포·로봇 상태(Damping)를 본다
2. **운영자 화면의 "수동 실행" 버튼 그리드는 비어 있다** (플릿 모드에서 허용목록이
   안 실리는 알려진 버그). 무대 경로는 정상이라 무대 전용 운영에는 지장 없다
3. 동작 완료는 추정이다 (뉴진스 32.2초). 그동안 다음 명령은 거부된다 —
   급하면 **정지 버튼**으로 잠금을 즉시 푼다

## 7. 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| 라디오 수가 모자람 | 전원·케이블·**위쪽 포트** 확인 → [USB 재탐색]. 허브 포트 부족/전류 부족 의심 |
| 특정 라디오만 "무응답" | 그 라디오의 **K1PC 화면이 닫힘**(재실행) 또는 VCP 가 CLI 로 리셋됨 |
| PC 에 아예 안 잡힘 | 충전 전용 케이블 / 아래쪽 USB-C / 라디오 전원 꺼짐 |
| **미믹이 1초 만에 끊김** | 그 라디오 **SB 하단** → 중앙으로 |
| 한 로봇만 안 움직임 | 그 로봇 다이얼 219 미등록, 뉴진스 자산 미배포, 또는 Damping 상태 |
| 영상은 나오는데 무음 | display 오디오 잠금 미해제 → 화면 한 번 탭 |
| 무대가 너무 일찍 끝남 | 프리셋을 "직접 설정"으로 시작했는지 확인 (저장 프리셋 사용 권장) |
| 외부 기기 로그인 안 됨 | HTTP 로 띄웠다 → `./start_stage.sh`(HTTPS) 로 재시작 |
| 사이트 접속 자체가 안 됨 | `tmux has-session -t rc-stage` 확인 → 없으면 `./start_stage.sh` |

## 8. 종료

```bash
tmux kill-session -t rc-stage      # 서버 종료
```
라디오는 K1PC 를 EXIT 하면 PC 제어에서 빠진다. 케이블을 뽑아도 된다(0.5초 내 자동 해제).
